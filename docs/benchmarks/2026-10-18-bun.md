# Bun migration measurements

Measured locally on 2026-10-18, macOS ARM64, Bun 1.4.3 and Node 24.7.0. The same compiled CLI and empty synthetic workspace are used in both runtime measurements. Update checks are disabled. Twelve fresh processes run per runtime; these are warm-filesystem measurements, not database latency promises.

| Measurement | Node | Bun | Reduction |
| --- | ---: | ---: | ---: |
| CLI `--version`, p50 | 21.390 ms | 5.942 ms | 72.2% |
| MCP initialization plus tool discovery, p50 | 109.166 ms | 62.420 ms | 42.8% |
| CLI `--version`, p95 | 26.312 ms | 7.535 ms | 71.4% |
| MCP initialization plus tool discovery, p95 | 123.064 ms | 69.431 ms | 43.6% |

The build now uses Bun's TypeScript transpiler and preserves module paths for lazy driver imports and Rust/WASM loading. Explicit type imports are enforced by TypeScript's `verbatimModuleSyntax` option. Type checking remains a separate required CI step.

Ten warm-cache build samples measured the previous TypeScript typecheck-and-emit at a median 727.99 ms, Bun transpile-and-copy at 16.93 ms, and independent type checking at 645.29 ms. The new complete typecheck-plus-build path is about 662.22 ms using those medians, about 9.0% lower. Comparing only Bun's 16.93 ms transpilation against the previous 727.99 ms would omit required validation.

The npm tarball is 716,463 bytes (2,751,187 unpacked) after the Bun build, versus 731,745 bytes immediately before migration: about 2.1% smaller compressed. It still contains the portable Rust policy runtime and legal notices. Bun itself is not bundled into the npm package. The curl installer downloads a checksum-verified private Bun only when needed. Existing npm/npx users run the same JavaScript with Node 22+.

Vitest, its coverage provider, rimraf, the old compiler-emit build, and the two npm lockfiles were removed. One `bun.lock` covers server and site workspaces. Native `bun:test` runs isolate files so module mocks cannot affect other tests. All 301 tests pass; live fixtures also pass on Bun for PostgreSQL, MySQL, MariaDB, SQL Server and Oracle, including deadline recovery. PostgreSQL/MySQL TLS-through-SSH tests pass on Bun. The packed CLI is checked under both Bun and Node; CI extends this to Node 22/24/26.

## Reproduce

```sh
bun install --frozen-lockfile
bun run typecheck
bun run build
bun run test
bun scripts/benchmark-startup.mjs dist/index.js
node scripts/benchmark-startup.mjs dist/index.js
node scripts/benchmark-build.mjs --bun=/absolute/path/to/bun
npm pack --dry-run --json --ignore-scripts
bun scripts/integration.mjs --engines=postgres,mysql,mariadb,mssql,oracle
bun scripts/check-tls.mjs
```

Run timing benchmarks without other builds or database fixtures in parallel. Raw observations: [Bun startup](2026-10-18-bun-startup.json), [Node startup](2026-10-18-node-startup-current.json), [build](2026-10-18-bun-build.json). The nearest-rank p95 is the slowest of twelve startup samples. Bun reports a Node compatibility version in `process.version`; each runtime report records the actual runtime and version separately.

Primary API references: [Bun transpiler](https://bun.sh/docs/runtime/transpiler), [Bun test isolation](https://bun.sh/docs/test/parallel), [Bun Node compatibility](https://bun.sh/docs/runtime/nodejs-compat). Runtime compatibility is tested against the project's actual drivers rather than inferred from these documents.
