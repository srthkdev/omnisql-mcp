# DuckDB execution and package cost

Measured on 2026-10-18, macOS ARM64, DuckDB CLI 1.5.6, Bun 1.4.3 and Node 26.3.0. The fixture contains 10,000 synthetic orders in a local database file. Each sample is a full MCP `SUM(total)` call after client initialization and three warmup pairs. Thirty pairs alternate unrestricted and restricted connections to the same file.

| Runtime | Unrestricted p50 / p95 | Table policy p50 / p95 |
| --- | ---: | ---: |
| Bun | 12.90 / 13.91 ms | 26.67 / 28.49 ms |
| Node | 12.37 / 13.39 ms | 26.00 / 28.30 ms |

Each query starts a bounded CLI process. A table policy adds one batched catalog process, including for joins. This has measurable overhead; this adapter does not claim to outperform an in-process DuckDB connection. It keeps the engine binary outside the npm package and provides process cancellation, locked safe mode, and the same authorization/result interface as the other engines. Native DuckDB computation, process startup, JSON parsing and MCP transport are included; first version checks and parser loading are excluded.

The npm tarball grows from 722,836 to 726,258 bytes, an increase of 3,422 bytes (0.47%). Unpacked size grows from 2,772,174 to 2,784,192 bytes. Both builds use the same locked dependencies and Rust binary. DuckDB adds no npm dependency; its separately installed CLI has its own size and is required for DuckDB connections.

Twelve fresh Bun processes gave median MCP readiness of 60.30 ms before and 59.84 ms after the adapter. That difference is too small to establish an improvement. The after sample includes a 126 ms outlier; raw samples are retained. This is a small sequential sample, not a controlled startup performance claim.

The real MCP fixture also checks exact nested DECIMAL/64-bit values, duplicate columns, index expressions and foreign keys, query plans, concurrent writes with truncated readers, timeouts, two database files, large result pages, compressed exports, and revoked handles. File and loopback HTTP canaries confirm that external scans fail without making an HTTP request. The same fixture runs on Bun and Node in CI against a checksum-verified Linux CLI.

```sh
bun run build
OMNISQL_BENCHMARK_REPORT_DIR=docs/benchmarks bun scripts/check-duckdb.mjs
OMNISQL_BENCHMARK_REPORT_DIR=docs/benchmarks node scripts/check-duckdb.mjs
```

Set `OMNISQL_DUCKDB_CLI` if the executable is outside PATH. Reports: [Bun](2026-10-18-duckdb-bun.json), [Node](2026-10-18-duckdb-node.json), [package](2026-10-18-duckdb-package.json), [startup](2026-10-18-duckdb-startup.json).
