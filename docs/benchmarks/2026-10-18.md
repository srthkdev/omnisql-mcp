# Startup and SQL-analysis measurements

Measured on 2026-10-18 with Node.js 24.7.0, macOS ARM64, and a local warm filesystem cache. These are local comparisons, not service-level latency promises.

| Measurement | Baseline | Updated | Change |
| --- | ---: | ---: | ---: |
| CLI `--version`, median of 12 fresh processes | 160.59 ms (published 2.2.0) | 20.84 ms | 87.0% lower |
| MCP initialization plus tool discovery, median of 12 fresh processes | 168.51 ms (published 2.2.0) | 78.13 ms | 53.6% lower |
| CLI peak RSS, median of 12 fresh processes | 117.78 MB (published 2.2.0) | 44.46 MB | 62.3% lower |
| SQL parsing/analysis, median per query over 6,000 queries | 0.0562 ms (node-sql-parser 5.4.0) | 0.0122 ms (Rust/WASM) | 78.2% lower |
| Parser module load plus six first queries | 43.62 ms (JavaScript) | 11.11 ms (Rust/WASM) | 74.5% lower |
| Parser process peak RSS | 152.81 MB (JavaScript) | 85.90 MB (Rust/WASM) | 43.8% lower |
| npm tarball after runtime work, before/after package cleanup | 777,712 bytes | 724,707 bytes | 6.8% lower |

The CLI now loads only argument handling for help/version commands. SQL drivers load when their engine is used. This reduces MCP initialization too; it does not remove network connection, authentication, or database execution costs. Connection pools address repeated connection overhead separately.

Rust replaces the JavaScript AST parser dependency. The existing small SQL tokenizer remains to reject comments and escaping rules that differ across SQL dialects. Its purpose differs from AST analysis. The Rust npm payload includes approximately 2 MB of portable WebAssembly plus license notices, so the package is larger than the original 2.2.0 package that had no AST policy analyzer. The alternative `node-sql-parser@5.4.0` npm package alone has a declared unpacked size of 92,373,153 bytes; that dependency was removed rather than shipped alongside Rust. No Rust compiler is needed by users. Release packages omit TypeScript declarations and source maps because this package exposes a CLI.

The parser comparison uses the same six PostgreSQL queries, all accepted by both parsers, with 300 warmup calls. JavaScript creates an AST; Rust also collects relations and functions and serializes its analysis to JSON. This is a parser workload comparison. It does not claim that database queries become 4.6 times faster. The two parsers support different dialect grammars.

`p95` in the startup JSON uses the nearest-rank method. With only 12 processes, p95 is the slowest sample and is sensitive to first-run cache effects. RSS and CLI timing were collected separately with `/usr/bin/time -l`; MCP initialization timing excludes the client's shutdown. RAM and MB values use decimal bytes.

## Reproduce

```sh
npm run build
node scripts/benchmark-startup.mjs /path/to/2.2.0/dist/index.js dist/index.js
node scripts/benchmark-parser.mjs rust
npm install --prefix /tmp/omnisql-parser-bench --no-audit --no-fund node-sql-parser@5.4.0
node scripts/benchmark-parser.mjs javascript /tmp/omnisql-parser-bench/node_modules/node-sql-parser
npm pack --dry-run --json --ignore-scripts
```

Raw observations: [startup](2026-10-18-startup.json), [CLI memory](2026-10-18-cli-memory.json), [parser](2026-10-18-parser.json). The startup commands deliberately use an empty synthetic workspace and disable update checks. They do not connect to personal databases.
